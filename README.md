# 心愿卡 · 网站双视角 AI Demo

一个以小红书商品生态为背景的礼赠决策网站 Demo。

## 项目逻辑

1. 阿杰先支付 500 元，形成仅用于本次礼物的心愿额度；
2. 小敏收到心愿卡，但看不到具体预算金额；
3. 小敏完成 8 道偏好问题；
4. 系统从有商品图片的商品池中推荐 3 件具体实体商品；
5. 小敏选择 1 件并完成模拟下单；
6. 剩余金额模拟原路退回阿杰。

## 页面结构

- 启动页：艺术体标题“心愿卡”和两个入口；
- 灵感来源页：四幕动画解释产品初衷；
- 双视角体验：左侧阿杰，右侧小敏；
- 左视角：填写观察、祝福和 500 元心愿额度；
- 右视角：打开心愿卡、完成 8 道问题、选择商品；
- 商品详情：商品图、价格、卖点、推荐理由；
- 完成页：模拟下单与送礼人侧退款状态。

## 本地运行

双击：

`启动网站.cmd`

默认地址：

`http://127.0.0.1:3030/`

不要直接双击 `index.html`，因为商品目录需要通过本地 HTTP 服务读取。

## Netlify 部署

仓库根目录已经包含 `netlify.toml`：

- Build command：留空；
- Publish directory：`.`；
- 不需要后端服务；
- 不需要安装依赖；
- 不需要环境变量。

## 技术结构

- `index.html`：页面结构；
- `styles.css`：视觉和动效；
- `app.js`：状态机、双视角交互、8 道问题、商品筛选与模拟订单；
- `assets/catalog/`：商品图片；
- `assets/catalog-100.json`：商品目录；
- `assets/fonts/`：本地字体；
- `assets/audio/`：音效与背景音乐；
- `assets/img/`：卡片、纸飞机和背景资源。

## 项目定位

心愿卡把送礼人的心意、收礼人的偏好和平台商品承接连接起来，先理解需求，再推荐具体商品。
